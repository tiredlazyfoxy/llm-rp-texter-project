## Where stat defs come from on the frontend

The world payload fetched by the admin SPA already includes
`stat_definitions` (used elsewhere for stat editing UIs in the
admin). Reuse that field — do not add a new fetch. If a page
fetches the world without stat defs, extend its existing fetcher;
do not introduce a separate stats-only endpoint.

## Regex pitfall

Don't accidentally widen the autocomplete trigger so far that it
starts matching things inside JSON-looking content the user
authors. Constrain to:

```
\{([A-Z][A-Z0-9_]*)(?::([A-Z][A-Z0-9_]*)?)?$
```

(or equivalent — the precise shape is the coder's choice, but it
must match `{INITIAL_MESSAGE`, `{USER`, `{USER:HE`, `{WORLD:`, and
must NOT match `{ "key"` or `{foo`).
