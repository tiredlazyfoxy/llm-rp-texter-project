# Step 003 — Editor LLM helper prompts learn the namespaced syntax

## Goal

Teach the document and world-field editor LLMs about
`{USER:NAME}` / `{WORLD:NAME}` by listing the world's actual
`WorldStatDefinition` names in their system prompts. The literal
syntax must appear (never a substituted value), so the editor
preserves the placeholder when generating prose.

## Files to create or modify

- `backend/app/services/document_editor_system_prompt.py` —
  builder learns to emit a stat section.
- `backend/app/services/world_field_editor_system_prompt.py` —
  same.
- `backend/tests/services/test_document_editor_system_prompt.py`
  and
  `backend/tests/services/test_world_field_editor_system_prompt.py`
  — assert the rendered prompt contains the expected stat names
  and the literal `{USER:` / `{WORLD:` syntax.

## Signatures

The existing builder functions keep their signatures. They already
receive a `World` (or world id + a way to load definitions). Inside,
they pass the world's `WorldStatDefinition` list to a new local
helper that renders a section like:

```
Stat placeholders (substituted at chat runtime, not now —
preserve them verbatim):

  User stats:
    {USER:HEALTH}     int
    {USER:INVENTORY}  set

  World stats:
    {WORLD:WEATHER}   enum
```

(Format: pick whichever rendering Feature 010 already used for the
runtime placeholder list — comma-separated inline vs bulleted —
and stay consistent. See `context.md` "Open trade-offs".)

## Tests

- Builder produces a prompt containing every `WorldStatDefinition`
  name from the test world.
- Each stat name appears as a literal `{USER:NAME}` or
  `{WORLD:NAME}` token.
- The prompt instructs the LLM to preserve placeholders verbatim
  (assert the imperative phrasing exists).
- A world with zero stats renders no stat section (or an explicit
  "no stats defined" line — pick one and test).
- Hidden stats are still listed (substitution is unaffected by
  `hidden`; see context.md decision 3).

## Definition of done

- Both builder modules call into a shared rendering helper (DRY)
  or each has its own — pick one and stay consistent.
- Both produce prompts that include the world's stat names with
  literal namespaced tokens.
- New tests pass.
- No runtime substitution leaks here: the builders must NOT call
  `apply_runtime_placeholders`; they must only emit literal text.

## Dependencies

- Independent of steps 001/002 in code, but logically should land
  after step 001 so the syntax is canonical when documented.
