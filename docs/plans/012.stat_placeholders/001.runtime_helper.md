# Step 001 — Runtime helper learns `{USER:NAME}` / `{WORLD:NAME}`

## Goal

Extend `RuntimePlaceholderContext` with stat-snapshot fields and
extend `apply_runtime_placeholders` to substitute namespaced stat
tokens, with the locked render rules and missing-name fallback.
Pure helper; tests-first.

## Files to create or modify

- `backend/app/services/runtime_placeholders.py` — extend TypedDict
  and helper.
- `backend/app/services/prompt_injection.py` — add a defensive
  comment near the existing `\{([A-Z_]+)\}` regex noting that
  namespaced tokens like `{USER:NAME}` are deliberately handled
  elsewhere and the regex must not be widened to match `:`.
- `backend/tests/services/test_runtime_placeholders.py` — extend
  with the new cases listed below (file already exists from
  Feature 010; add cases, do not rewrite).

## Signatures

Widen the existing TypedDict:

```
class RuntimePlaceholderContext(TypedDict, total=False):
    # ...existing Feature 010 fields preserved...
    stat_definitions: list[WorldStatDefinition] | None
    stat_values: dict[tuple[str, str], ChatStat] | None
    # key shape: (owner, name) where owner in {"user", "world"}
    # value: ChatStat row currently set on the chat
```

(If the coder picks a precomputed lookup map instead of the raw
list, document the choice in `status.md` Notes — see context.md
"Open trade-offs".)

`apply_runtime_placeholders` keeps its existing public signature:

```
def apply_runtime_placeholders(
    text: str, ctx: RuntimePlaceholderContext
) -> str
```

Internally it gains a new regex pass that runs before/after the
existing token pass (order chosen to avoid double-substitution).
The new pattern matches `\{(USER|WORLD):([A-Z_][A-Z0-9_]*)\}`.

## Tests

Add to `backend/tests/services/test_runtime_placeholders.py`:

- `int` stat renders as `str(value)`.
- `enum` stat renders as the enum value string.
- `set` stat renders as comma-space joined; empty set renders as
  empty string.
- Hidden stat (`hidden=True`) DOES substitute.
- Unknown name renders as empty string and emits a DEBUG log
  (assert with `caplog`).
- Unknown owner namespace (e.g. `{NPC:FOO}`) is left untouched
  (regex matches only `USER` and `WORLD`).
- Tokens with lowercase letters in the name (e.g. `{USER:Health}`)
  are left untouched (regex requires uppercase).
- An empty/None `stat_definitions` and `stat_values` yields empty
  string substitution + DEBUG log without raising.
- The existing Feature 010 placeholders still substitute correctly
  (regression).
- The `prompt_injection.resolve_prompt_template` regex still does
  not match `{USER:NAME}` (regression test in
  `test_prompt_injection.py` if absent — otherwise add a single
  assertion).

## Definition of done

- `RuntimePlaceholderContext` has the new fields, typed precisely;
  no `Any`.
- `apply_runtime_placeholders` substitutes the new tokens per the
  render rules locked in `context.md`.
- Missing name and unknown owner cases never raise.
- DEBUG log emitted on missing name; format includes the
  unresolved token.
- All new and existing tests in
  `backend/tests/services/test_runtime_placeholders.py` pass.
- `prompt_injection.py` has the defensive comment.
- `apply_runtime_placeholders` remains pure: no DB calls, no
  service imports beyond model types.

## Dependencies

None. This step is self-contained and tests-first.
