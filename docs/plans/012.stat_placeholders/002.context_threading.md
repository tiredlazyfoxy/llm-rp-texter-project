# Step 002 — Thread stat snapshots through chat-runtime contexts

## Goal

Populate the new `stat_definitions` and `stat_values` fields on
`RuntimePlaceholderContext` at every chat-runtime entrypoint so the
helper from step 001 has data to substitute. Editor-bound paths
remain unchanged.

## Files to create or modify

- `backend/app/services/chat_context.py` — extend
  `_build_runtime_ctx` (or equivalent constructor) to load the
  world's `WorldStatDefinition`s and the chat's `ChatStat`s and
  attach them.
- `backend/app/services/chat_service.py` — initial-message branch
  that builds the runtime ctx (from Feature 010); attach the new
  fields.
- `backend/app/services/chat_agent_service.py` — chat-bound
  `ToolContext` builder; attach the new fields.
- `backend/app/services/simple_generation_service.py` — chat-bound
  `ToolContext` builder.
- `backend/app/services/chain_generation_service.py` — chat-bound
  `ToolContext` builder.
- `backend/app/services/admin_tools.py` — **CONFIRMED UNCHANGED.**
  Verify in review that this file is not modified.
- `backend/tests/services/test_chat_context.py` (and analogous
  tests for the four chat-runtime services) — assert the new
  fields are populated when a chat has stats.

## Signatures

No new public signatures. The `RuntimePlaceholderContext` shape is
the contract from step 001; this step only fills it.

If a small private helper is useful (e.g. `_load_chat_stats(chat)`)
it lives in `services/stat_service.py` (or `db/chats.py` if it is a
pure query) — pick the layer per the layer-separation rule. Suggest:

```
async def load_chat_stat_snapshot(
    chat_id: int,
) -> tuple[list[WorldStatDefinition], dict[tuple[str, str], ChatStat]]
```

…implemented as service-layer composition over `db/` queries.

## Tests

- For each chat-runtime entrypoint, build the ctx for a chat that
  has at least one `int`, one `enum`, one `set`, and one `hidden`
  stat. Assert all four appear in `ctx["stat_values"]` and the
  corresponding definitions appear in `ctx["stat_definitions"]`.
- For an editor-bound path (whichever is closest analogue), assert
  the dummy/empty ctx has `stat_definitions` and `stat_values` set
  to `None` (or empty) — i.e. step 002 does NOT leak stats into
  editor flows.
- End-to-end: render a string containing `{USER:HEALTH}` through
  one chat-runtime path and confirm substitution; render the same
  string through an editor path and confirm the placeholder
  remains literal.

## Definition of done

- All five listed chat-runtime entrypoints attach the new fields.
- `admin_tools.py` is byte-identical to its pre-step state (verify
  via `git diff`).
- Editor-bound contexts continue to produce a stat-less ctx and
  the helper leaves namespaced tokens as empty strings (per step
  001 fallback). Editor LLMs see the literal token in their
  prompts (covered by step 003).
- New tests pass; existing tests for these services still pass.
- No DB queries land in services or routes; new query helpers (if
  any) live in `db/`.

## Dependencies

- Step 001 must be merged: needs the widened
  `RuntimePlaceholderContext` shape and the helper that consumes
  the new fields.
