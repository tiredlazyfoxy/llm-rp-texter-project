## Auth gating

The user SPA already exposes `auth.role` (admin / user) in its
auth state. Use the existing flag — do not introduce a new
permissions concept. Backend gating in step 004 is the source of
truth; frontend gating is UX sugar.

## SSE refresh — do not duplicate

The user SPA already subscribes to chat SSE events and handles
`stat_update` (emitted today by the LLM `set_stat` tool path). The
admin endpoint reuses that event name (step 004), so the existing
handler refreshes the UI without changes. Step 006 must not add a
second handler or a manual post-submit refetch.

## Edit widget reminders

- `enum` — `<select>` with the definition's allowed values.
- `set` — multi-select (whatever multi-select primitive the user
  SPA already uses; do not introduce a new component library).
