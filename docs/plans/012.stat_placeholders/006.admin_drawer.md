# Step 006 — Admin-only stat editor drawer in `ChatViewPage`

## Goal

Mount an admin-only drawer on `ChatViewPage` that lets an
authenticated admin edit `ChatStat` values for the current chat.
The drawer mirrors the layout of the existing `ChatSettingsPanel`,
calls the new `PUT /api/chats/{chat_id}/stats` endpoint, and
relies on the existing `stat_update` SSE handler to refresh the
visible state.

## Files to create or modify

- `frontend/src/user/components/StatEditorDrawer.tsx` (new) —
  drawer component, modeled on `ChatSettingsPanel`.
- `frontend/src/user/state/chatPageState.ts` — add drawer-open
  state, submit action, and dependency on `auth.role === "admin"`
  for the trigger visibility.
- `frontend/src/user/api/chats.ts` — add typed `updateChatStats`
  client.
- `frontend/src/user/api/chats.d.ts` (or wherever the user API
  types live) — add request/response interfaces matching the
  Pydantic models from step 004 exactly.
- `frontend/src/user/pages/ChatViewPage.tsx` — render the trigger
  button only when `auth.role === "admin"` and mount the drawer.
- Component test for `StatEditorDrawer` (visibility gating + submit
  payload shape) at the project's existing user-SPA test location.

## Signatures

API client:

```
export interface StatUpdateItem {
  owner: "user" | "world";
  name: string;
  value: number | string | string[];
}

export interface UpdateChatStatsRequest {
  updates: StatUpdateItem[];
}

export interface UpdateChatStatsResponse {
  chat_id: number;
  applied: StatUpdateItem[];
}

export async function updateChatStats(
  chatId: number,
  body: UpdateChatStatsRequest
): Promise<UpdateChatStatsResponse>;
```

`chatPageState` additions:

```
class ChatPageState {
  // ...existing...
  statDrawerOpen: boolean;
  openStatDrawer(): void;
  closeStatDrawer(): void;
  submitStatUpdates(updates: StatUpdateItem[]): Promise<void>;
}
```

`StatEditorDrawer` props: receive the world's stat definitions and
the chat's current stat values (already in the page's MobX state),
plus `onSubmit` / `onClose` callbacks.

## Tests

- Drawer trigger is not rendered when `auth.role !== "admin"`.
- Drawer trigger is rendered when `auth.role === "admin"`.
- Submit calls `updateChatStats` with exactly the typed payload.
- Editing widgets respect stat kind:
  - `int` → number input
  - `enum` → single-select from allowed values
  - `set` → multi-select from allowed values
- After a successful submit, the existing `stat_update` SSE
  handler updates the visible state (verified by simulating an
  SSE event in test or by checking the handler is the same one
  used today).
- 403 from the backend (e.g. role check fails server-side) is
  surfaced as a user-visible error in the drawer.

## Definition of done

- Drawer renders only for admins (frontend gating).
- Submit hits the new admin endpoint with the correct typed
  payload.
- No `any` anywhere in the new TypeScript.
- The existing `stat_update` SSE handler powers the post-submit
  refresh — no parallel refresh logic.
- Component tests pass.
- The drawer does not modify `WorldStatDefinition` rows; it only
  edits per-chat values.
