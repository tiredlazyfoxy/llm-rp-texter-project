# Step 005 — Frontend authoring surfaces (badge + autocomplete + helper)

## Goal

Make `{USER:NAME}` / `{WORLD:NAME}` first-class on the admin
authoring surfaces: placeholder badge panel, inline `{PARTIAL`
autocomplete, and the LLM helper system prompt — for both
`DocumentEditPage` and `WorldFieldEditPage`.

## Files to create or modify

- `frontend/src/admin/state/placeholderAutocompleteState.ts` —
  widen the trigger regex so `:` is permitted inside a partial
  match (e.g. `{USER:HE` should still trigger and complete).
- `frontend/src/admin/components/PlaceholderBadgePanel.tsx` (or
  the existing badge module) — render new badges sourced from
  `buildStatPlaceholders(statDefs)`.
- `frontend/src/admin/state/placeholders/buildStatPlaceholders.ts`
  (new) — pure helper that converts a list of
  `WorldStatDefinition` into the badge model used by the panel and
  autocomplete.
- `frontend/src/admin/pages/DocumentEditPage.tsx` — pass the
  world's stat defs into the badge panel + autocomplete state.
- `frontend/src/admin/pages/WorldFieldEditPage.tsx` — same.
- Tests for the helper and the autocomplete regex (whichever test
  framework / location the project already uses for
  `placeholderAutocompleteState`).

## Signatures

```
// buildStatPlaceholders.ts
export interface StatPlaceholder {
  token: string;        // e.g. "{USER:HEALTH}"
  label: string;        // e.g. "USER:HEALTH"
  owner: "user" | "world";
  kind: "int" | "enum" | "set";
  hidden: boolean;
}

export function buildStatPlaceholders(
  defs: WorldStatDefinition[]
): StatPlaceholder[];
```

`placeholderAutocompleteState.ts` regex change: the existing
trigger pattern (matches the partial token after `{`) must accept
`:` and uppercase letters/digits/underscore so that typing
`{USER:HE` opens the dropdown filtered to `{USER:HEALTH}`.

## Tests

- `buildStatPlaceholders` produces one badge per stat def, with
  the correct `token` string and owner.
- Autocomplete regex matches `{USER:HE`, `{WORLD:W`, `{INITIAL_M`
  (existing Feature 010 tokens), and does NOT match plain `{`
  alone.
- DocumentEditPage and WorldFieldEditPage component tests assert
  that with a world that has stats, the badge panel renders
  `{USER:*}` and `{WORLD:*}` chips.

## Definition of done

- Both pages show stat badges next to the existing Feature 010
  badges.
- Autocomplete completes namespaced tokens.
- LLM helper request payload (the prompt sent to the editor LLM —
  built by step 003 on the backend) is unchanged on the frontend
  side; this step does not touch the helper request shape.
- No `any`. New `.d.ts` updates if the world payload's stat defs
  weren't already exposed; otherwise none.
- Existing Feature 010 autocomplete and badge tests still pass.

## Dependencies
