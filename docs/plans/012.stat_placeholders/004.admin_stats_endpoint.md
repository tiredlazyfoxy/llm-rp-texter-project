# Step 004 — Admin endpoint `PUT /api/chats/{chat_id}/stats`

## Goal

Add an admin-only HTTP endpoint that updates one or more
`ChatStat` rows on a chat, reusing the existing
`stat_service.validate_and_apply_stat_updates` helper, and emits
the same `stat_update` SSE event the LLM `set_stat` tool path
emits. Strictly typed Pydantic request/response.

## Files to create or modify

- `backend/app/routes/chats.py` — register the new route.
- `backend/app/schemas/chats.py` (or wherever chat request models
  live) — add request/response Pydantic models.
- `backend/app/services/stat_service.py` — confirm
  `validate_and_apply_stat_updates` is reusable as-is. If it
  currently only handles single-stat updates, add a thin
  multi-stat wrapper here (do not duplicate validation logic).
- `backend/tests/routes/test_chats_stats_admin.py` (new) — route
  tests.

## Signatures

Pydantic schemas:

```
class StatUpdateItem(BaseModel):
    owner: Literal["user", "world"]
    name: str
    value: int | str | list[str]
    # int for kind=int, str for kind=enum, list[str] for kind=set

class UpdateChatStatsRequest(BaseModel):
    updates: list[StatUpdateItem]

class UpdateChatStatsResponse(BaseModel):
    chat_id: int
    applied: list[StatUpdateItem]
```

Route:

```
@router.put(
    "/api/chats/{chat_id}/stats",
    response_model=UpdateChatStatsResponse,
    dependencies=[Depends(require_admin)],
)
async def update_chat_stats(
    chat_id: int,
    payload: UpdateChatStatsRequest,
) -> UpdateChatStatsResponse: ...
```

(Adjust `require_admin` to whatever the existing admin dependency
is named in this codebase.)

Service-layer (reuse or thin wrapper around existing function):

```
async def apply_admin_stat_updates(
    chat_id: int,
    updates: list[StatUpdateItem],
) -> list[StatUpdateItem]: ...
```

Internally calls `validate_and_apply_stat_updates` per item (or in
batch if the existing function already accepts a list).

**SSE emit dropped (user resolution, option 1).** There is no
shared `stat_update` emit helper and no chat-scoped SSE channel
outside an in-flight LLM streaming generator (the existing
`stat_update` events are inline `queue.put(...)` calls into the
per-request streaming queue). The admin endpoint therefore does
NOT emit SSE; the response itself returns the applied state, and
the admin drawer (step 006) refreshes from that response. See
`status.md` → "Step 004 — BLOCKED (escape valve)" for the full
analysis.

## Tests

- 200 OK for an admin user with valid updates: response echoes the
  applied list.
- 403 for a non-admin authenticated user.
- 401 for unauthenticated.
- 404 when `chat_id` does not exist.
- 422 when request validation fails (e.g. `value` type does not
  match stat kind — surfaced by the existing validation helper).
- An invalid stat name returns the same error shape the LLM tool
  surfaces today (consistency).

## Definition of done

- Endpoint registered and admin-gated.
- All Pydantic models strictly typed; no `dict[str, Any]`.
- Service path reuses `validate_and_apply_stat_updates` — no
  duplicated validation, no direct DB access in the route or
  service.
- Response echoes the applied updates (used by step 006 to refresh
  the drawer). No SSE emit (see note above).
- New route tests pass.
- No DB schema or JSONL importer changes.

## Dependencies
