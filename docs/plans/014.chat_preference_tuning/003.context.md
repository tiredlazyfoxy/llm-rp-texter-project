Chain pipeline map is in `context.md`; feedback row field contract is in
`context.md`. Step-specific anchors:

## Regenerate flow (current)

- Route: `POST /api/chats/:id/regenerate` → `routes/chat.py:142-153`, body
  `RegenerateRequest{ turn_number: int|None }` (`chat.py:202-203`).
- Service: `chat_agent_service.regenerate_response(session_id, user_id,
  caller_role, turn_number)` ~:258-311 — dispatches on `pipeline.kind` to
  `chain_generation_service.regenerate_chain_response`.
- `regenerate_chain_response(session_id, user_id, caller_role, pipeline)` ~:808:
  captures old stats/location, appends `_msg_to_variant(...)` to variants,
  `_save_variants`, deletes the active assistant message, reads
  `user_instructions` from the stored user msg (~:854), emits `variants_update`
  SSE (~:906). The discarded assistant message (its `content` and
  `generation_plan`) is available here before deletion — capture the feedback
  snapshot from it.

## Writer-only regen building blocks

- `_run_writer_stage` ~:401 (phase "writing") rebuilds writer_messages from
  summaries + active msgs + `build_writing_plan_message`, minimal ToolContext,
  model `stage.model_id or chat.text_model_id`.
- `_run_chain_generation` loop ~:663 iterates `pipeline.stages`; writer-only
  regen runs only the writer stage(s) and skips tool stages. Reuse
  `_finalize_chain` (~:699) to commit.
- Prior plan source: `GenerationVariant.generation_plan`
  (`models/schemas/chat.py:124-135`) and `ChatMessage.generation_plan` (JSON).
  `build_writing_plan_message` already turns a plan into the writer-injection
  message.

## Feedback write

Use `db/generation_feedback.insert` (step 001). Snowflake id via
`from app.services import snowflake as snowflake_svc; snowflake_svc.generate_id()`
in the service layer before insert. Write the rejected row BEFORE deleting the
active assistant message so the snapshot is still available.

## Schema location & new fields

`RegenerateRequest` at `backend/app/models/schemas/chat.py:202-203`. Add two
optional fields: `scope` — accepts only the literal strings `"plan"` or
`"text"`, or null; `comment` — free text or null. Both default to absent/null so
existing callers still validate. (Exact annotation is the skeleton agent's call.)
