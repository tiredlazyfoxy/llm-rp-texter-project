## Reject affordances + comment precedent

Chain mode has three reject affordances (see the step file): two one-click fast
rejects and one "reject with comment". Key rules for this UI:

- **A comment only ever pairs with `scope="plan"`.** Both fast rejects are
  one-click and comment-less (fast "reject" → `scope="plan"`; fast "reject
  generation" → `scope="text"`). Only "reject with comment" carries a `comment`,
  and it always uses `scope="plan"`. Never send a comment with `scope="text"`.
- **The comment UI must surface the rejected content.** The "reject with comment"
  input displays the generation being rejected (the just-streamed assistant
  message / latest variant) so the user can reference it. That content is already
  available client-side — do NOT add a new fetch.
- The reject "comment" is a plain free-text field sent on the regenerate request
  (step 005); it does NOT reuse the `((...))` OOC message syntax. OOC parsing
  precedent for reference only:
  `frontend/src/utils/oocParser.ts` `extractUserInstructions(text)` (regex
  `/\(\((.+?)\)\)/gs`).

## Chain-mode detection

The reject affordances are chain-mode only. Determine chain mode from the chat's
pipeline kind already available to the page state / message components (same
signal used elsewhere to branch chain vs simple UI). Confirm the exact field
during coding; do not invent a new one.
