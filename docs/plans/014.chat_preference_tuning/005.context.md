# Step 005 context

SSE protocol + preferences-API framing are in `context.md`. Step-specific
anchors:

## Backend

- Routes live in `backend/app/routes/chat.py` (HTTP only — parse, call service,
  return). The tuning GET/PUT go here next to the existing chat routes.
- New service `tuning_service.py` imports `from app.db import tuning_profiles`
  and assigns snowflake ids via
  `from app.services import snowflake as snowflake_svc`.
- Reuse the step-001 Pydantic schemas in `models/schemas/chat.py` (profile
  response + update request).

## Frontend transport anchors

- `frontend/src/api/chat.ts`: `regenerateMessage(chatId, handlers, turnNumber?)`
  (SSE), `continueChat(chatId, {variant_index})`, `sendMessage`. SSE parser is
  the private `_streamChat`; `ChatSSEHandlers` already has
  `onPhase/onStatus/onVariantsUpdate/onDone/...` — add `onTuningUpdate` and a
  `tuning_update` case in `_streamChat`.
- DTOs: `frontend/src/types/chat.d.ts` — `RegenerateRequest{turn_number?}`,
  `SendMessageRequest`, `ContinueRequest`, `GenerationVariant`, `ChatMessage`.
  Mirror backend exactly; no runtime validation.
- User-global settings precedent for the new profile client/types:
  `frontend/src/types/userSettings.d.ts`, `frontend/src/api/userSettings.ts`,
  `frontend/src/utils/translationSettings.ts`.
