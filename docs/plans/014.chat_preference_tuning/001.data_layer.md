## Interface intent

- **`ChatTuningProfile` SQLModel** — table for per-(user, world) tuning text.
  Columns: snowflake `id` (primary key, no default), `user_id`, `world_id`,
  `plan_tuning` (text, default empty string), `tone_tuning` (text, default
  empty string), `created_at`, `modified_at`. Follow the `ChatMemory` template
  for snowflake-id + simple columns and timestamp handling. There is no DB-level
  unique constraint required; logical uniqueness on `(user_id, world_id)` is
  enforced by the db module's lookup-then-upsert.
- **`ChatGenerationFeedback` SQLModel** — table for one generation attempt's
  verdict, session-scoped. Columns: snowflake `id`, `session_id` (FK
  `chat_sessions.id`), `turn_number`, `verdict` (`"approved"`/`"rejected"`),
  `scope` (`"plan"`/`"text"`/null), `comment` (text|null), `content_snapshot`
  (text), `plan_snapshot` (JSON string|null), `created_at`.
- **`db/tuning_profiles.py`** — session-free namespace module. Functions:
  - get the profile for a `(user_id, world_id)` pair, returning `None` if absent.
  - upsert a profile row (create-or-update) via `session.merge`, mirroring the
    `db/user_settings.py` `upsert` pattern. Caller (service) supplies the
    snowflake `id` on first create.
- **`db/generation_feedback.py`** — session-free namespace module. Functions:
  - insert one feedback row.
  - list feedback rows for a `(session_id, turn_number)`, ordered by
    `created_at` ascending (the retune step reads the turn's rejects).
  - delete all feedback rows for a `session_id` (used by the cascade).
- **`engine.py`** — add `import app.models.chat_tuning_profile  # noqa: F401`
  and `import app.models.chat_generation_feedback  # noqa: F401` to the existing
  noqa import block so `create_all` builds the tables.
- **`db/chats.py` `delete_session`** — add a call to delete this session's
  feedback rows, placed in FK order alongside the other related-row deletes.
- **`db_import_export.py`** — add a `_chat_tuning_profile_to_dict` /
  `_dict_to_chat_tuning_profile` pair and a
  `_chat_generation_feedback_to_dict` / `_dict_to_chat_generation_feedback`
  pair, copying the `_chat_memory_to_dict` / `_dict_to_chat_memory` pattern
  (use `_serialize_datetime` / `_parse_datetime` for timestamps). Append both
  registry tuples to `TABLE_REGISTRY`, each placed **after** any parent table it
  FK-references (feedback after `chat_sessions`; tuning profile after `users`
  and `worlds`).
- **Pydantic API schemas in `models/schemas/chat.py`** — a response schema for
  the tuning profile (`plan_tuning`, `tone_tuning`, string-serialized id +
  world id) and a request schema for updating it (`plan_tuning`, `tone_tuning`).
  These are the contract consumed by steps 004/005. No feedback schema is
  surfaced to the API in this feature.

## Definition of done

1. [test] Both SQLModel tables are created by `create_all` after `init_db()`
   (assert the tables exist / a row can be inserted and read back). (DoD-1)
2. [test] `db/tuning_profiles.get` returns `None` for an unknown
   `(user_id, world_id)`, and after an `upsert` returns the stored row with the
   same `plan_tuning` / `tone_tuning`; a second `upsert` for the same pair
   updates in place rather than creating a duplicate. (DoD-2)
3. [test] `db/generation_feedback`: insert + list-by-(session, turn) returns
   rows in `created_at` order; delete-by-session removes them. (DoD-3)
4. [test] JSONL export then import round-trips a `ChatTuningProfile` row and a
   `ChatGenerationFeedback` row with all fields (including null `scope`/
   `comment`/`plan_snapshot`) intact. (DoD-4)
5. [test] `db/chats.delete_session` removes the session's
   `ChatGenerationFeedback` rows (none orphaned after delete). (DoD-5)
6. [manual/live] `TABLE_REGISTRY` ordering places both new tuples after their
   FK parents (reviewed, not asserted). (DoD-6)
7. [manual/live] API schemas serialize `id` / `world_id` as strings per the
   project ID convention. (DoD-7)
