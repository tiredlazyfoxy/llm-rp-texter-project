# Step 001 context

Feature-wide facts (table field contract, conventions, JSONL rule) live in
`context.md`. Step-specific anchors:

## Templates to copy

- **Model template**: `backend/app/models/chat_memory.py` — cleanest snowflake-id
  + simple-column + timestamp model. Use it as the shape for both new models.
- **Per-user prefs precedent**: `backend/app/models/user_settings.py` (PK is
  `user_id`, no FK). Precedent for a small prefs table, but our profile is per
  `(user_id, world_id)` with its own snowflake PK — do NOT make `user_id` the PK.
- **db module template**: `backend/app/db/user_settings.py` — `get(user_id)` +
  `upsert(settings)` via `session.merge`. Each fn opens
  `session = await get_standalone_session(); async with session: ...`.
- **Chat db access**: `backend/app/db/chats.py`; `delete_session` (~:116)
  manually deletes related rows in FK order — add the feedback delete there.

## Registration / import-export anchors

- `backend/app/db/engine.py` noqa import block ~lines 9-16; `init_db()` (~:68)
  runs `create_all` + ad-hoc `ALTER TABLE` migrations (no Alembic). New model
  files MUST be imported here or the table is never created.
- `backend/app/services/db_import_export.py`:
  - `TABLE_REGISTRY` at ~:590-607 — list of
    `(zip_filename, model_class, to_dict_fn, from_dict_fn)` 4-tuples.
  - `_chat_memory_to_dict` / `_dict_to_chat_memory` pattern at ~:570-587 — copy it.
  - `_serialize_datetime` / `_parse_datetime` at ~:44 / ~:48.
  - Generic `export_table` / `upsert_batch` in `db/import_export_queries.py`
    need NO changes.

## ChatSession / world FK references

- `ChatSession` (`backend/app/models/chat_session.py`) has `user_id` (FK
  `users.id`) and `world_id` (FK `worlds.id`) — use the same FK targets for the
  profile's `user_id`/`world_id` if FKs are declared on the new model.
- `ChatGenerationFeedback.session_id` references `chat_sessions.id`.

## Gotcha

SQLite drops timezone info on datetimes — normalize with
`.replace(tzinfo=timezone.utc)` when comparing/parsing (see project memory).

## Size note

This step touches many files but each change is small (two ~20-line models, two
~40-line db modules, ~2-line engine edit, ~5-line cascade, ~40-line import/export,
~30-line schemas). It sits near the 200-LoC upper bound but is a single cohesive
data-layer slice; do not split unless the coder finds it exceeds 200.
