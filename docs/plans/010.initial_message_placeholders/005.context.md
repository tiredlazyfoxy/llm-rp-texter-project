## Admin tools stay raw

`backend/app/services/admin_tools.py`:
- `search_impl` interpolates `doc.content` at lines 131/135/139.
- `get_lore_impl` interpolates `doc.content` at line 164.

Do **not** modify these. The document-editor's own LLM chat (and
any future editor-mode tool surface) calls them directly and must
see literal `{CHARACTER_NAME}` so the AI learns to emit the token
unchanged. The substitution distinction is the central decision of
this step.

## ToolContext call sites to populate

The briefing names three plausible chat-bound construction sites:
- `chat_agent_service.py`
- `simple_generation_service.py`
- `chain_generation_service.py`

Coder grep `ToolContext(` to enumerate them all. Every chat-bound
call site receives a `ChatSession` (or equivalent) from which the
character name and current location can be derived; the
`RuntimePlaceholderContext` is built once per request and stored
on the `ToolContext` object.

Editor-bound call sites (document-editor LLM chat, world-field-
editor LLM chat) leave the field as its default `None`.

## Current-location semantics

Same decision as step 004: `LOCATION_NAME` and `LOCATION_SUMMARY`
resolve to the **current** location at the time the tool is
called, never the starting location. The current location must
already be loaded by the calling service before
`ToolContext.runtime_placeholders` is built (it is — every chat-
bound generation path loads it for its own reasons).
