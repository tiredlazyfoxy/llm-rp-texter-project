# Step 003 — context

## Mirror of `PipelineStageEditPage`

The wiring template the coder mirrors lives in
`frontend/src/admin/pages/PipelineStageEditPage.tsx` around
lines ~43 (controller ref) and ~69-76 / ~158-178 (panel render +
onInsert handler). After step 002 those imports come from
`../components/placeholders/...` instead of
`../components/pipelines/...`; otherwise the wiring shape is
identical and is the canonical reference for the new
`WorldFieldEditPage` branch.

## Why a controller ref and not a callback prop

`docs/architecture/frontend-components.md` ("Imperative API
escape valve") explicitly endorses
`controllerRef?: RefObject<XController | null>` for this
two-method case (`insertAtCursor`). Use that pattern; do not
introduce a new state class or hoist autocomplete state into
`worldFieldEditPageState`.

## Token literal at insert time

`PlaceholderPanel`'s `onInsert(name)` callback receives the bare
name (`CHARACTER_NAME`). The page wraps it as `'{' + name + '}'`
before calling `controllerRef.current?.insertAtCursor(...)` —
same as `PipelineStageEditPage`. The
`INITIAL_MESSAGE_PLACEHOLDERS` constants therefore store the
**unbraced** name only.

## "Used" highlighting

`PlaceholderPanel` highlights tokens already present in the
content via `content.includes('{${name}}')` (~harvested from
the panel source). The page passes the current draft value of
`initial_message` as the `content` prop so the highlight stays
live while the user types. No additional plumbing needed.

## Field branch

`WorldFieldEditPage` already handles two fields via
`state.fieldName`. The new code is a single branch in the JSX
where the textarea currently renders (around lines ~105-113 per
the harvest). Keep the rest of the page (header, `LlmChatPanel`,
save/cancel) untouched.
