# Step 005 — Backend: chat_tools runtime substitution

## Goal

Apply runtime placeholder substitution to every chat-side tool
that returns document content (location, NPC, memory, lore, search
results), using the helper from step 004. Editor-side
(`admin_tools.py`) calls remain raw so the AI editor sees literal
`{CHARACTER_NAME}` and learns the syntax.

## Files to create or modify

Modify:
- `backend/app/services/chat_tools.py` — extend `ToolContext`
  with an optional `runtime_placeholders: RuntimePlaceholderContext | None`
  field and apply substitution in:
  - `get_location_info_impl` (line 118; substitution sites at the
    `location.content` interpolation around line 139 and the NPC
    briefs around line 161)
  - `get_npc_info_impl` (line 171; the `npc.content` interpolation
    around line 192)
  - `move_to_location_impl` (line 236; the `location.content` use
    around line 279)
  - `get_memory_impl` (line 210; the joined `ChatMemory.content`)
  - the `_b_search` and `_b_get_lore` bindings (lines 351-363)
    that delegate to `admin_tools.search_impl` /
    `admin_tools.get_lore_impl` — wrap their returns with
    `apply_runtime_placeholders` when `ToolContext.runtime_placeholders`
    is set.
- The site(s) that build `ToolContext` for chat-bound tool
  execution. Likely candidates per the briefing:
  `chat_agent_service.py`, `simple_generation_service.py`,
  `chain_generation_service.py`. Coder identifies all sites by
  grepping for `ToolContext(` constructor calls; each chat-bound
  call site populates `runtime_placeholders` from
  `session.character_name` + the session's **current** location
  name and content. Editor-bound call sites (the document-editor
  LLM chat, world-field-editor LLM chat) leave the field as
  `None`.
- `backend/app/services/admin_tools.py` — **no changes**.
  `search_impl` (lines 131/135/139) and `get_lore_impl` (line 164)
  remain raw. The chat-side substitution happens only in the
  chat_tools wrappers/bindings.

Tests:
- Extend `backend/tests/services/test_chat_tools.py` (create if it
  does not exist) — for each chat-side tool listed above, assert:
  - When `ToolContext.runtime_placeholders` is set, returned text
    has all three tokens substituted.
  - When `runtime_placeholders` is `None` (editor mode), returned
    text contains the raw tokens.
- Extend `backend/tests/services/test_chat_service.py` — assert
  `move_to_location` substitution end-to-end (move into a location
  whose `content` contains `{CHARACTER_NAME}`; assert the user-
  visible output substitutes it).

## Signatures

```python
# backend/app/services/chat_tools.py
from app.services.runtime_placeholders import (
    RuntimePlaceholderContext,
    apply_runtime_placeholders,
)

@dataclass  # or whatever the existing decorator/base is — preserve it
class ToolContext:
    # ... existing fields unchanged ...
    runtime_placeholders: RuntimePlaceholderContext | None = None
```

(Coder confirms the existing class definition shape — dataclass,
TypedDict, plain class — and adds the new field as `Optional[...]`
with default `None` so all existing callers keep working without
modification. Only chat-bound call sites are updated to pass it.)

The four `_impl` functions and the two `_b_*` bindings keep their
current signatures; the substitution happens inside their bodies
via `apply_runtime_placeholders(result, ctx.runtime_placeholders)`
just before returning. No public API change.

## Definition of done

- `ToolContext` carries an optional `runtime_placeholders`
  context.
- Every chat-side tool that returns document content substitutes
  the three placeholders when the context is present and returns
  raw text when it is not.
- `admin_tools.py` is unchanged; editor-mode tool calls remain
  raw.
- All chat-bound `ToolContext(...)` construction sites populate
  the new field from session character + current location.
- All listed tests pass.
- No `session` / `AsyncSession` / `select()` leaks into routes
  (layer separation preserved).
