# Step 006 — Backend: editor system prompts learn the placeholders

## Goal

Teach both LLM-assisted editor system prompts about the three
runtime placeholder tokens so the AI writes content that uses
them where appropriate. Update the document-editor system prompt
(currently silent on placeholders) and expand the world-field
editor's `initial_message` role from a one-liner to a coherent
multi-line section consistent with the document-editor block.

## Files to create or modify

Modify:
- `backend/app/services/prompts/document_editor_system_prompt.py`
  — `build_document_editor_system(...)` at line 46. Add a
  "## Runtime Placeholders" section listing the three tokens with
  one-line semantics each, explaining "use these where you would
  write the player's name or the current location — they
  substitute at chat time before the player ever sees the text".
  The section appears for every `doc_type` value (location, npc,
  lore_fact). One block, included unconditionally.
- `backend/app/services/prompts/world_field_editor_system_prompt.py`
  — `_FIELD_ROLES["initial_message"]` lines 43-47. Replace the
  current one-liner mention with a multi-line block mirroring the
  document-editor block's wording. Use **doubled** `{{...}}`
  escaping so that the surrounding `.format(world_name=...)` call
  at line 146 leaves the literal `{CHARACTER_NAME}` intact in the
  output. `_FIELD_ROLES["description"]` is **not** modified —
  description does not get runtime substitution.

Tests:
- `backend/tests/services/prompts/test_document_editor_system_prompt.py`
  (create or extend) — snippet-checks that
  `build_document_editor_system(...)` output contains:
  - the substring `Runtime Placeholders`
  - each of `{CHARACTER_NAME}`, `{LOCATION_NAME}`, `{LOCATION_SUMMARY}`
  - the explanation phrase indicating "substitute at chat time"
    (or the exact phrase the planner picks — verifier checks
    against whichever phrase the coder writes, as long as it
    conveys runtime substitution).
- `backend/tests/services/prompts/test_world_field_editor_system_prompt.py`
  (create or extend) — same snippet check applied to the
  `initial_message` branch, plus a regression assert that the
  `description` branch does **not** contain the placeholders
  block.

## Signatures

No public-API signature changes. Both prompt builders keep their
existing parameter lists. Only the string content they emit
changes.

The placeholders block is the same trio established by feature
010 — no new tokens are introduced in this step.

## Tests

- `test_document_editor_system_prompt.py`
  - `doc_type="location"`, `doc_type="npc"`, and
    `doc_type="lore_fact"` each include the placeholders block.
  - The three tokens appear literally (uppercase, in braces).
  - The explanation phrase mentions chat-time substitution.
- `test_world_field_editor_system_prompt.py`
  - `field_name="initial_message"` output includes the
    placeholders block with all three tokens (literal braces, not
    escaped) — confirming the doubled-brace escaping survived
    `.format(world_name=...)`.
  - `field_name="description"` output does **not** include the
    placeholders block.

## Definition of done

- Both prompt builders emit a coherent "Runtime Placeholders"
  section listing all three tokens.
- The world-field editor prompt's doubled-brace escaping is
  correct: the rendered prompt contains literal `{CHARACTER_NAME}`,
  not `CHARACTER_NAME` and not `{{CHARACTER_NAME}}`.
- `description` field role is unchanged.
- All listed tests pass.
- No other prompt-building paths regress (existing tests still
  pass).

## Dependencies

None as a build dependency. Conceptually sits downstream of step
004 (the placeholder vocabulary it teaches the AI is the same one
the helper substitutes), but the steps can land in any order.
