# Step 001 — Backend: uppercase placeholders + migration

## Goal

Normalize all `initial_message` placeholder tokens to UPPERCASE in
runtime substitution, the AI editor's system prompt docstring, and
existing DB rows; ensure JSONL re-import does not re-introduce
lowercase tokens.

## Files to create or modify

- `backend/app/services/chat_service.py` (modify) — runtime
  substitution at lines 425-432.
- `backend/app/services/prompts/world_field_editor_system_prompt.py`
  (modify) — placeholder list in the docstring (~lines 43-47).
- `backend/app/db/worlds.py` (modify, or whichever module under
  `backend/app/db/` owns world rows — coder confirms by reading
  the file) — add an idempotent
  `normalize_initial_message_placeholders()` data-migration helper
  that runs over every world row.
- DB init path (modify) — wire the migration to run once on
  startup. The exact module is `backend/app/db/__init__.py` or
  `backend/app/main.py`'s startup event, depending on how prior
  data migrations are bootstrapped; coder picks the consistent
  spot.
- World JSONL importer (modify) — apply the same uppercase
  substitution to `initial_message` while reading rows. The exact
  path lives in the import/export module under
  `backend/app/services/` (by project convention,
  `db_import_export.py` or similar — coder confirms).
- Tests:
  - `backend/tests/services/test_chat_service.py` (modify or
    create) — assert the three uppercase tokens are substituted at
    chat start.
  - `backend/tests/db/test_initial_message_migration.py` (create)
    — covers the migration helper.

## Signatures

```python
# backend/app/db/worlds.py  (or the existing worlds db module)

async def normalize_initial_message_placeholders() -> int:
    """
    Rewrite lowercase placeholder tokens in every World.initial_message
    to their uppercase form. Idempotent. Returns the number of rows
    actually changed.
    """
```

The substitution map (single source of truth — define as a
module-level constant in the same file):

```python
INITIAL_MESSAGE_TOKEN_REWRITES: tuple[tuple[str, str], ...] = (
    ("{character_name}", "{CHARACTER_NAME}"),
    ("{location_name}",  "{LOCATION_NAME}"),
    ("{location_summary}", "{LOCATION_SUMMARY}"),
)
```

A thin pure helper used by both the migration and the importer:

```python
def rewrite_initial_message_tokens(text: str) -> str:
    """Apply INITIAL_MESSAGE_TOKEN_REWRITES; idempotent."""
```

(Lives next to `INITIAL_MESSAGE_TOKEN_REWRITES`. The importer
imports it; the chat service does **not** — the chat service does
the runtime *value* substitution, which is a separate concern.)

## Tests

- `test_initial_message_migration.py`
  - Seeds three worlds: one with all-lowercase tokens, one with
    all-uppercase tokens, one with a mix.
  - Runs `normalize_initial_message_placeholders()`.
  - Asserts every row's `initial_message` contains only uppercase
    tokens; lowercase versions are gone.
  - Runs the migration a second time; asserts return value is `0`
    (idempotent — no rows changed on the second pass).
- `test_chat_service.py`
  - Existing tests for `initial_message` substitution updated to
    use the uppercase tokens.
  - New assertions: `{CHARACTER_NAME}`, `{LOCATION_NAME}`,
    `{LOCATION_SUMMARY}` are each replaced with the expected value
    when the chat is started.
  - Assert that lowercase variants are **not** substituted (the
    runtime no longer recognizes them — migration is the only
    path).

## Definition of done

- `chat_service.py` lines 425-432 substitute uppercase tokens
  only.
- `world_field_editor_system_prompt.py` docstring lists the three
  uppercase tokens (and only those) as the available placeholders
  for the AI editor.
- `normalize_initial_message_placeholders()` exists in the `db/`
  layer, is idempotent, and is called once during DB init.
- World JSONL importer applies `rewrite_initial_message_tokens`
  to `initial_message` before upsert.
- All listed tests pass.
- No `session` / `AsyncSession` / `select()` leaks into services
  or routes (layer separation preserved).
- Existing tests in the chat-service suite still pass.
