# Step 004 — Backend: runtime placeholder helper + chat_context substitution

## Goal

Introduce a single, centralized runtime placeholder substitution
helper (`apply_runtime_placeholders` + `RuntimePlaceholderContext`),
refactor the existing `chat_service.py` `initial_message` substitution
to use it, and apply it inside `chat_context.py` so that location,
NPC, and lore content are substituted before they enter the chat
prompt.

## Files to create or modify

Create:
- `backend/app/services/runtime_placeholders.py` — pure helper
  module. No I/O. No DB. No imports from `app.db.*`. Lives in
  `services/` because both `chat_service.py` and `chat_context.py`
  consume it; placing it in `db/` would invert the layering.
- `backend/tests/services/test_runtime_placeholders.py` — pure
  helper tests.

Modify:
- `backend/app/services/chat_service.py` — replace the inline
  `.replace()` chain at lines 426-432 with a single
  `apply_runtime_placeholders(initial_message, ctx)` call. The
  context is built locally from the freshly-resolved character +
  starting location.
- `backend/app/services/chat_context.py` — three substitution
  sites inside `build_chat_context(session)`:
  1. line 69 — `location_description = location.content`
  2. line 92 — joined `injected_lore` of `WorldLoreFact.content`
  3. lines 146-160 — inside `_format_npcs_at_location`, the
     `npc.content.split("\n\n")[0]` brief.
  Build a `RuntimePlaceholderContext` once at the top of
  `build_chat_context` from `session.character_name`,
  `current_location.name`, `current_location.content` and reuse it
  for all three sites. Thread the context into
  `_format_npcs_at_location` as a new parameter.
- `backend/tests/services/test_chat_service.py` — update to ensure
  the refactor preserves existing behavior (the three uppercase
  tokens are still substituted in `initial_message` at chat start).
- `backend/tests/services/test_chat_context.py` (create if it does
  not exist; otherwise extend) — new cases for location.content,
  lore_fact.content, and NPC brief substitution using **current**
  location, not starting.

## Signatures

```python
# backend/app/services/runtime_placeholders.py

from typing import TypedDict

class RuntimePlaceholderContext(TypedDict):
    character_name: str
    location_name: str
    location_summary: str

def apply_runtime_placeholders(
    text: str,
    ctx: RuntimePlaceholderContext | None,
) -> str:
    """
    Substitute the three runtime placeholder tokens in `text`:
        {CHARACTER_NAME}    -> ctx["character_name"]
        {LOCATION_NAME}     -> ctx["location_name"]
        {LOCATION_SUMMARY}  -> ctx["location_summary"]

    If `ctx` is None, returns `text` unchanged. Pure: no I/O, idempotent
    on already-substituted text (only literal token strings are touched).
    """
```

The token set is the same trio already established by feature 010:
`{CHARACTER_NAME}`, `{LOCATION_NAME}`, `{LOCATION_SUMMARY}`. This
helper is the **only** runtime substitution implementation in the
backend going forward.

The signature for `_format_npcs_at_location` (currently at
`chat_context.py` line 146-ish) gains a new last parameter:

```python
async def _format_npcs_at_location(
    world_id: int,
    location_name: str,
    runtime_placeholders: RuntimePlaceholderContext | None,
) -> str:
    ...
```

## Tests

- `test_runtime_placeholders.py`
  - All three tokens are substituted with the matching context
    field.
  - `ctx=None` returns the input unchanged.
  - Idempotent: running the helper twice on already-substituted
    text yields identical output (no double substitution because
    only literal token strings are touched).
  - Lowercase variants (`{character_name}` etc.) are **not**
    substituted — the runtime contract is uppercase only (consistent
    with step 001).
  - Text with no tokens returns unchanged.

- `test_chat_service.py` (updated)
  - The existing initial_message-substitution test continues to
    pass after the refactor.
  - Asserts `apply_runtime_placeholders` is the substitution path
    (smoke check via the externally visible result).

- `test_chat_context.py` (new or extended)
  - Seed a session at a non-starting current location whose
    `WorldLocation.content` contains `{LOCATION_NAME}` and
    `{CHARACTER_NAME}`; assert the rendered context substitutes
    them with the **current** location's name and the session
    character name.
  - Seed an injected lore fact whose `content` contains
    `{LOCATION_NAME}`; assert it is substituted.
  - Seed an NPC at the current location whose `content` brief
    contains `{CHARACTER_NAME}`; assert the brief is substituted.

## Definition of done

- `runtime_placeholders.py` exists and exposes
  `RuntimePlaceholderContext` and `apply_runtime_placeholders`.
- `chat_service.py` lines 426-432 are replaced by a single
  `apply_runtime_placeholders(...)` call; behavior is preserved
  for existing tests.
- `chat_context.py` substitutes location.content, lore_fact.content,
  and NPC content briefs using the **current** location (not the
  starting location).
- All listed tests pass.
- No `session` / `AsyncSession` / `select()` leaks into services
  or routes (layer separation preserved — the helper is pure and
  imports nothing from `app.db.*`).
- `apply_runtime_placeholders` is the single substitution
  implementation; no other module re-implements the same
  `.replace()` logic.
