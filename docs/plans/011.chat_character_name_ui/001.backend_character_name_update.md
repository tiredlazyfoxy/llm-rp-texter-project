# Step 001 — Backend: editable `character_name` + non-empty validation

## Goal

Make `character_name` an editable field on the chat-settings update
flow, and tighten Pydantic validation so empty / whitespace-only
values are rejected with HTTP 400 on **both** create and update —
with the trimmed value being the one persisted.

## Files to create or modify

- `backend/app/models/schemas/chat.py` (modify) —
  - `CreateChatRequest.character_name`: tighten with a trim-and-
    reject validator (line 17).
  - `UpdateChatSettingsRequest`: add `character_name: str | None =
    None` (lines 38-40) with the same trim-and-reject validator
    applied when present (`None` skips validation; empty string or
    whitespace-only string fails).
- `backend/app/services/chat_service.py` (modify) — the existing
  update-settings service function (currently mutating
  `tool_model` / `text_model`) accepts and forwards
  `character_name` when present in the request. The trimmed value
  reaches the DB layer; coder confirms the function name by
  following `UpdateChatSettingsRequest` usage.
- `backend/app/db/chats.py` (modify) — the existing settings-
  update DB helper (the one the service calls for
  `tool_model` / `text_model`) gains a `character_name: str | None
  = None` parameter and persists it when not `None`. Coder
  confirms the helper's exact name by following its call site.
- `backend/app/routes/chat.py` (no change expected) — the existing
  `PATCH` settings handler already forwards
  `UpdateChatSettingsRequest` to the service; the new field rides
  through unchanged. Coder verifies no route-level work is
  required and notes the file untouched in `status.md`.
- `backend/tests/models/test_chat_schemas.py` (create or extend if
  it exists) — Pydantic-level validator tests.
- `backend/tests/services/test_chat_service.py` (modify) —
  service-level update-flow test for `character_name`.
- `backend/tests/db/test_chats.py` (create or extend if it
  exists) — db-layer persistence test.

## Tests

- `test_chat_schemas.py`
  - `CreateChatRequest`: empty string for `character_name` raises
    `ValidationError`; whitespace-only (`"  "`, `"\t\n"`) raises;
    leading/trailing whitespace is trimmed
    (`"  Aria  "` → `"Aria"`); non-empty value passes through.
  - `UpdateChatSettingsRequest`: `character_name=None` is fine;
    empty string raises; whitespace-only raises;
    leading/trailing whitespace is trimmed.
- `test_chat_service.py`
  - Existing test asserting initial `character_name` substitution
    still passes.
  - New test: `update_chat_settings(payload=...)` with a fresh
    `character_name` updates the row; calling `chat_service`-side
    runtime context (or reading the row directly) reflects the
    new value.
  - Update with `character_name=None` leaves the existing value
    untouched.
- `test_chats.py` (db layer)
  - `update_chat_settings(character_name="Bob")` writes the
    field; the row read back has `character_name == "Bob"`.
  - `update_chat_settings(character_name=None,
    tool_model="model-x")` updates `tool_model` only and leaves
    `character_name` unchanged.
- `test_chat_routes.py` (only if such a file already exists in
  the repo) — HTTP-level: `PATCH` with empty `character_name`
  yields 400; `PATCH` with `"Aria"` yields 200 and the response
  body's `character_name` is `"Aria"`.

## Definition of done

- `UpdateChatSettingsRequest` exposes `character_name: str | None
  = None` with a trim-and-reject validator.
- `CreateChatRequest.character_name` rejects empty / whitespace-
  only inputs and trims the value.
- The chat-service update function and its db-layer counterpart
  both accept and persist `character_name` end-to-end.
- HTTP 400 is returned for empty / whitespace-only on both create
  and update (this is automatic via the validator + FastAPI's
  default `RequestValidationError` handling; coder confirms by
  inspection).
- All listed tests pass; pre-existing chat-service / chat-route
  tests continue to pass.
- Layer separation preserved: no `session` / `AsyncSession` /
  `select()` outside `db/`.
- No SQLModel / table change; no JSONL import/export change.
- `chat_session.character_name` (the SQLModel column) is
  untouched.
