# Step 003 — Accept path → fire-and-forget; remove inline retune + `tuning_update` SSE

## Goal

Change the accept hook so it writes the `approved` row then, only when the accepted
turn had ≥1 reject, schedules a background retune via the step-002 registry
(non-blocking), and remove all inline-retune emitter/SSE plumbing.

## Source files

backend/app/services/chat_service.py
backend/app/services/chain_generation_service.py
backend/app/services/simple_generation_service.py
backend/app/services/retune_service.py

## Test files

backend/tests/services/test_accept_fire_and_forget.py

## Interface intent

- **`chat_service._record_accept_and_retune(...)`** — keep writing the single
  `verdict="approved"` `ChatGenerationFeedback` row via `feedback_db.create(...)`.
  Then apply the D2 auto-trigger gate here: read the accepted turn's rows via
  `feedback_db.list_by_turn(session_id, turn_number)` and, only if that turn had ≥1
  `verdict="rejected"` row, call `retune_tasks.start(session_id, user_id, world_id,
  model_id, turn_number)`. This is fire-and-forget — do NOT `await` the retune LLM;
  `start` returns immediately. Remove the `emitter` parameter and the direct
  `await retune_service.maybe_retune(...)` call. A clean turn (no rejects) schedules
  nothing.
- **`retune_service`** — remove `maybe_retune`'s emitter parameter and its
  `tuning_update` emission entirely (the step-001 core is what the registry calls;
  if `maybe_retune` remains as a thin wrapper it must be emitter-free, or it may be
  removed if now unused — skeleton decides based on remaining callers).
- **`chain_generation_service.py:826-856` auto-commit** — remove the buffered
  `_emit`/`pending_frames` construct used ONLY for `tuning_update` and the
  `for frame in pending_frames: yield frame` loop that flushed it. Call the
  emitter-free `_record_accept_and_retune(...)` (no `emitter=` argument). Editor
  frames unrelated to tuning (if any share `pending_frames`) must be preserved —
  only the `tuning_update` path is removed; if `pending_frames` existed solely for
  `tuning_update`, drop it entirely. The `verdict="rejected"` reject-row write at
  `chain_generation_service.py:953` is unchanged.
- **`simple_generation_service.py:373-391` auto-commit** — call the emitter-free
  `_record_accept_and_retune(...)`; it already passed `emitter=None`, so this is a
  signature-alignment change. (Simple mode writes no reject rows, so the gate makes
  it a guaranteed no-schedule — matches D4.)
- **`chat_service.continue_chat` (:655)** — the explicit-accept caller already
  passed `emitter=None`; align to the new emitter-free signature. Same
  gate-and-schedule behavior applies.

## Definition of done

1. `[test]` Accepting a turn returns without awaiting the retune LLM — the accept
   path completes while the scheduled background job is still pending (non-blocking).
   (DoD-1)
2. `[test]` When the accepted turn had ≥1 reject row, `retune_tasks.start(...)` is
   invoked with the session/user/world/model/turn arguments. (DoD-2)
3. `[test]` When the accepted turn had zero reject rows (clean accept),
   `retune_tasks.start(...)` is NOT invoked. (DoD-3)
4. `[test]` The `approved` `ChatGenerationFeedback` row is still written on accept
   regardless of the gate outcome. (DoD-4)
5. `[test]` No `tuning_update` SSE frame is produced by the chain auto-commit path
   (the event is gone). (DoD-5)
6. `[test]` `retune_service` exposes no emitter parameter and emits no
   `tuning_update` (dead emitter plumbing removed). (DoD-6)
7. `[manual/live]` All three accept routes (explicit `continue_chat`, chain
   auto-commit, simple auto-commit) compile and call through the unified emitter-free
   hook. (DoD-7)

## Dependencies

001 (emitter-free core), 002 (`retune_tasks.start` registry API).
