# Step 001 — Session-wide feedback + retune core

## Goal

Make the retune core read **all rejects across the whole session** (every turn) as
LLM evidence and drop the SSE emitter, so retune is a pure profile-persisting
function.

## Source files

backend/app/db/generation_feedback.py
backend/app/services/retune_service.py
backend/app/services/prompts/retune_prompt.py

## Test files

backend/tests/services/test_retune_service_session_wide.py

## Interface intent

- **`generation_feedback.list_by_session(session_id)`** (new, in
  `db/generation_feedback.py`) — returns all `ChatGenerationFeedback` rows for the
  session across every turn, ordered by `created_at` ascending (same ordering
  contract as the existing `list_by_turn`). Session-free DAL function, sibling to
  `create` / `list_by_turn` / `delete_by_session`. No schema change; no
  import/export change.
- **Retune core in `retune_service.py`** — refactor the retune body so the
  dimension-partitioning + LLM completion + upsert logic reads its reject evidence
  from `list_by_session(session_id)` (all turns) instead of
  `list_by_turn(session_id, turn_number)`. The turn-number gate does NOT live here
  anymore (per D2 it moves to the accept call site in step 003); the core assumes it
  was asked to run and simply aggregates whatever session-wide rejects exist. It
  must still no-op when `model_id is None`, still partition session rejects into the
  plan dimension (`scope` `plan`/`null`) and tone dimension (`scope` `text`/`null`),
  still run one `_retune_dimension` completion per targeted dimension, and still
  persist via `tuning_profiles_db.upsert(...)`. When there are zero session rejects,
  it is a fast no-op (no LLM call, no upsert). Expose this core under a clear name
  the background registry (step 002) and the accept path (step 003) can call; the
  precise signature is the skeleton agent's call, but it must accept
  session/user/world identifiers plus `model_id` and must NOT accept an emitter.
- **`RetuneEmitter` + `tuning_update` emission** — remove from `retune_service.py`
  (the type alias, the emitter parameter, and the emit call). Retune now persists to
  the profile only.
- **`retune_prompt.py`** — if the evidence-assembly helper assumes a single turn's
  rejects, adjust it so the prompt reflects rejects gathered across multiple turns
  (e.g. it should not label the evidence as "this turn"). Keep any change inside this
  one prompt file; keep the 5-section docstring intact and update its CHANGELOG
  section.

## Definition of done

1. `[test]` `list_by_session(session_id)` returns rows from multiple turns of the
   same session, ordered by `created_at` ascending, and excludes rows from other
   sessions. (DoD-1)
2. `[test]` The retune core aggregates rejects across all turns of the session:
   given rejects on turn 1 and turn 2, both contribute to the dimension evidence.
   (DoD-2)
3. `[test]` Dimension partitioning is preserved: `plan`/`null` scoped rejects feed
   the plan dimension, `text`/`null` scoped rejects feed the tone dimension, and only
   targeted dimensions run a completion. (DoD-3)
4. `[test]` The core no-ops (no LLM call, no upsert) when `model_id is None`. (DoD-4)
5. `[test]` The core no-ops when the session has zero reject rows. (DoD-5)
6. `[test]` On a session with rejects and a non-null `model_id`, the retuned result
   is persisted via `tuning_profiles_db.upsert(...)`. (DoD-6)
7. `[test]` `retune_service` no longer exposes `RetuneEmitter` and the retune core
   signature has no emitter parameter. (DoD-7)
8. `[manual/live]` `retune_prompt.py` prompt text no longer implies single-turn
   evidence; CHANGELOG updated. (DoD-8)
