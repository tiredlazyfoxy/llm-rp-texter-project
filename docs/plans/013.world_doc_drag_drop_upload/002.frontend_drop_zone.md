# Step 002 — Frontend: drag-and-drop drop zone on the documents table

## Goal

Wrap the documents table area inside `DocsTab` (in
`WorldViewPage.tsx`) with a native HTML5 drag-and-drop drop zone,
gated on `state.docTypeFilter` truthiness. Show drag-over visual
feedback. On drop, validate that **every** dropped file has an
accepted extension (`.md` / `.txt`); if any file has a different
extension, **reject the whole drop** and surface a clear error via
the existing `state.docsError` (no partial upload). If all files
are accepted, call the existing
`uploadDocuments(state, files, docType, signal)` mutation. The
existing "Upload Locations / Upload NPCs" menu and its hidden
`<input type="file">` stay in place.

## Signatures

`worldViewPageState.ts` additions:

```
class WorldViewPageState {
  // ...existing observables...
  dropActive: boolean;          // new — gates drag-over visual state
  // (or: dropDepth: number — see open trade-off)

  setDropActive(value: boolean): void;
  // (or matching depth-counter actions)
}
```

(The exact field name and shape — single boolean vs depth counter —
is the coder's call per the open trade-off in `context.md`.)

No change to `uploadDocuments` (module-level mutation) — its
existing signature
`uploadDocuments(state, files: File[], docType: string, signal?)`
is reused unchanged.

`DocsTab` (or extracted `DocsTableDropZone`) drag handlers — all
are typed `React.DragEventHandler<HTMLElement>` (or the more
specific wrapper element type), never `any`:

- `handleDragEnter(e)` — `preventDefault`; `setDropActive(true)`
  (or increment depth).
- `handleDragOver(e)` — `preventDefault` (required for `drop` to
  fire). May set `e.dataTransfer.dropEffect = "copy"`.
- `handleDragLeave(e)` — `preventDefault`; `setDropActive(false)`
  when leaving the wrapper (or decrement depth and clear at zero).
- `handleDrop(e)` — `preventDefault`; clear drop-active state;
  read `Array.from(e.dataTransfer.files)`; if **any** file has an
  extension outside `.md` / `.txt`, set `state.docsError` to a
  clear "drop rejected: only .md / .txt files are accepted"
  message via a `runInAction` and return without calling the API.
  Otherwise call
  `uploadDocuments(state, files, state.docTypeFilter!, signal)`.
  An empty `files` list (no items) is a no-op (no error, no call).

## Tests

Per Feature 008/012 precedent (`frontend/package.json` has no test
runner — see Feature 012 status notes step 005/006), no automated
frontend tests. Verification is manual + `npm run build`:

- `cd frontend && npm run build` is clean (tsc + vite, no errors,
  no `any`).
- Manual smoke test on each typed tab (`location`, `npc`,
  `lore_fact`):
  - Drag a `.md` file over the table → drop-active visual appears;
    drop uploads and the row appears after refresh.
  - Drag a `.txt` file → same.
  - Drag a `.png` file mixed with a `.md` file → drop is rejected
    as a whole; `state.docsError` shows a clear message; no API
    call is made; the `.md` file is NOT uploaded.
  - Drag only `.png` files → drop rejected the same way;
    `state.docsError` shows the message; no upload call.
  - Drag onto an empty table → drop still works.
- Manual smoke on the `all` tab → no drop-zone wrapper, dragging
  files does nothing (browser default may navigate, which is fine
  because we explicitly do not own the drop on `all`).
- Manual smoke on the `info` and `chats` tabs → unaffected
  (the wrapper is gated on `state.docTypeFilter` truthy, which
  excludes `all`, `info`, `chats`).

## Definition of done

- Documents table area on the `location`, `npc`, and `lore_fact`
  tabs is a drop target. Empty table is still a drop target.
- The `all`, `info`, and `chats` tabs are NOT drop targets.
- Dropping `.md` / `.txt` files calls
  `uploadDocuments(state, files, state.docTypeFilter!, signal)`
  and the documents list refreshes via the existing
  `refreshDocs`/whatever path the existing mutation uses.
- Mixed file types: if **any** dropped file is outside
  `.md` / `.txt`, the whole drop is rejected — `state.docsError`
  is set with a clear message, no API call is made, no files
  are uploaded.
- Existing "Upload Locations / Upload NPCs" menu and hidden
  `<input type="file">` continue to work unchanged.
- Drag-over visual feedback (border / overlay) appears while a
  file is being dragged over the wrapper, and clears on
  `dragleave` / `drop` without flicker (use depth counter or
  equivalent if needed — see open trade-off in `context.md`).
- All four drag handlers call `e.preventDefault()` where the spec
  requires it (`dragover` and `drop` at minimum); the page does
  not navigate to the dropped file.
- No `useState`, `useMemo`, `useCallback`, or custom hooks
  introduced. New observable lives on `WorldViewPageState`. The
  drop-zone wrapper component (inline or extracted) is
  `observer`-wrapped.
- No `any` in the new TypeScript; drag-event handlers are
  `React.DragEventHandler<HTMLElement>` or more specific.
- `npm run build` is clean.
