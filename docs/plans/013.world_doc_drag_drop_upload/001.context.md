# Step 001 — Step-specific context

## What this step touches that no other step does

- `backend/app/services/world_editor.py::upload_documents` — only
  this step modifies it.
- `WorldLoreFact` row shape — only this step needs the field
  inventory:
  - `id: str` (snowflake string per the existing convention)
  - `world_id: int`
  - `content: str`
  - `is_injected: bool` (default `False`)
  - `weight: int` (default `0`)
  - `created_at`, `modified_at` (datetime; same helper the
    `location` / `npc` branches use)
  - **No `name` field.** This is the reason the previous code
    rejected `lore_fact` for upload (the upsert-by-name path
    didn't apply). The new branch sidesteps that by always
    creating a new row.

## Current rejection (what to remove)

`services/world_editor.py:548-552` (per harvester report) raises:

```
HTTPException(
    status_code=400,
    detail="Upload is not supported for lore_fact type (no name to match on)",
)
```

Remove that branch. Add a `lore_fact` create branch that mirrors
the structure of the `location` / `npc` branches — same snowflake
helper, same timestamp helper, same `_index_document` call, same
`DocumentSaveResponse` construction shape.

## Route layer is unchanged

`backend/app/routes/admin/worlds.py:263-282` already accepts
`doc_type` as a `Query(...)` and `_validate_doc_type` (called
inside the service for `create_document` / `upload_documents`)
already accepts `"lore_fact"`. The route reads each `UploadFile`
as bytes and decodes UTF-8, which works for the `.md` / `.txt`
files the frontend will send.

## Test discovery

The harvester did not name a specific upload test file. Before
writing tests, search for an existing upload test:

- `backend/tests/services/test_world_editor*.py`
- `backend/tests/routes/admin/test_worlds*.py`

If a test file already covers the `location` / `npc` upload paths,
add the new `lore_fact` cases next to them. Otherwise create a new
test file in the matching directory.

## Reference branches (do not paste; just mirror their shape)

The `location` and `npc` branches in the same function are the
authoritative reference for:

- which snowflake helper to call,
- which timestamp helper to call,
- how the result is wrapped into `DocumentSaveResponse`,
- how `embedding_warning` is set.

The `lore_fact` branch should differ only in the model class and
the absence of a name/exits field.

## Out of scope for this step

- Frontend changes (step 002).
- Adding a "Upload Lore Facts" entry to the Upload menu — the
  existing menu only lists Locations and NPCs and stays that way
  in this feature; lore facts are uploaded via the new drop zone
  only.
- Schema changes to `DocumentSaveResponse` (the existing schema
  already has `name: str | None`, so a `None` name on the
  lore-fact response is legal).
