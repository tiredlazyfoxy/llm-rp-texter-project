# Step 001 — Backend: extend `upload_documents` to accept `lore_fact`

## Goal

Remove the explicit `lore_fact` rejection in
`services/world_editor.upload_documents` and replace it with a
branch that bulk-creates one new `WorldLoreFact` per uploaded
file, returning the same `list[DocumentSaveResponse]` shape the
existing `location` / `npc` branches return. The route layer and
all schemas stay unchanged.

## Files to create or modify

- `backend/app/services/world_editor.py` — replace the lines that
  raise `HTTPException(400, "Upload is not supported for lore_fact ...")`
  with a per-file `WorldLoreFact` create branch; reuse the
  module's existing snowflake-id helper, timestamp helper, and
  `_index_document` indexing call (whatever the `location` / `npc`
  branches use).
- `backend/tests/` — add a `lore_fact` upload case alongside the
  existing upload-route or upload-service tests. Discover the
  exact path by inspecting current upload coverage; if there is no
  pre-existing upload test file, create
  `backend/tests/services/test_world_editor_upload.py` or
  `backend/tests/routes/admin/test_worlds_documents_upload.py`
  (whichever directory matches sibling tests for this surface).

## Signatures

The public service signature is unchanged:

```
async def upload_documents(
    world_id: int,
    files: list[tuple[str, str]],   # (filename, utf-8-decoded content)
    doc_type: str,                  # "location" | "npc" | "lore_fact"
) -> list[DocumentSaveResponse]: ...
```

New internal behavior (descriptive — no implementation here, that
is the coder's job):

- When `doc_type == "lore_fact"`:
  - For each `(filename, content)`:
    - Generate a snowflake id (same helper used by the existing
      `location` / `npc` branches).
    - Insert a new `WorldLoreFact(id=<snowflake>, world_id=<int>,
      content=<file content>, ...)` with default
      `is_injected=False`, `weight=0`, and `created_at`/`modified_at`
      set via the same helper the other branches use.
    - Index via the existing `_index_document` (or whichever
      indexer the other branches call) so embeddings/search stay
      consistent.
  - No upsert: every file becomes a new row. Filename is discarded.
  - Aggregate the per-file `DocumentSaveResponse` results into a
    single returned list, in input order.
- The `embedding_warning` field on `DocumentSaveResponse` follows
  the same convention the existing branches use (set when the
  indexer reports a warning; otherwise `None`).

## Tests

In the chosen test file:

- **Upload `lore_fact` with two `.md` files** → 200 OK; response
  has two `DocumentSaveResponse` items, each with `doc_type ==
  "lore_fact"`, `world_id` matching, `content` equal to the file
  content, `name` of `None` (lore facts have no name), distinct
  snowflake `id`s, and `is_injected == False`, `weight == 0`.
- **Upload `lore_fact` with zero files** → 200 OK with an empty
  list (no error).
- **Upload `lore_fact` persists rows** → after the call, querying
  `WorldLoreFact` for that `world_id` yields the new rows.
- **`lore_fact` upload no longer raises 400** → directly assert the
  service does not raise for `doc_type == "lore_fact"` (regression
  guard — the previous behavior was an explicit `HTTPException`).
- **`location` / `npc` upload paths are untouched** — keep at
  least one happy-path test for each of those existing branches
  (or rely on existing coverage if it already exists; verify it
  still passes).
- **Auth gate intact** — non-editor caller still gets 403 (rely on
  existing route-level coverage if present; if there is no
  existing test asserting this for the upload route specifically,
  add one).

## Definition of done

- The `lore_fact` rejection branch in
  `services/world_editor.upload_documents` is gone.
- The new `lore_fact` branch creates one `WorldLoreFact` per
  uploaded file with the correct fields and indexes them via the
  same helper the other branches use.
- Upload route signature, request shape, and response shape are
  unchanged. No new Pydantic schemas. No DB schema change. No
  JSONL importer change.
- New tests cover the `lore_fact` happy path, zero-file case, and
  persistence. Existing `location` / `npc` upload tests still
  pass. Editor auth gate still enforced.
- Layer separation preserved — no DB queries in the route, no HTTP
  artifacts (`HTTPException`, `Query`, `UploadFile`) leaking out
  of the service for the new branch.
- `pytest backend/tests` is green.

## Dependencies

- None. Backend-only and self-contained; can land before, after,
  or in parallel with step 002.
