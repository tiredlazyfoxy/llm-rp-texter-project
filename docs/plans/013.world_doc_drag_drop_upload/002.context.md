## Native HTML5 DnD gotchas

- **`preventDefault` is required on `dragover` AND `drop`.**
  Without it, the browser navigates to the file URL and the drop
  event silently does not fire on your handler.
- **`dragleave` fires on every descendant boundary crossing**, so
  toggling visual state on every event causes flicker. Use a depth
  counter (`++` on `dragenter`, `--` on `dragleave`, clear visual
  state at zero) or check `relatedTarget` against the wrapper's
  bounds. Counter approach is simpler.
- **`e.dataTransfer.files`** is a `FileList` (not an array). Use
  `Array.from(e.dataTransfer.files)`.
- **`e.dataTransfer.dropEffect = "copy"`** in `dragover` gives the
  user a clear cursor affordance; optional but nice.

The codebase has zero existing drag-drop precedent (harvester
confirmed: no `@mantine/dropzone` or `react-dropzone`, no
`onDrop` / `onDragOver` matches anywhere in `frontend/`). Do not
add a library — native DnD covers this.

## "All files filtered out" error

When `Array.from(e.dataTransfer.files).filter(isAccepted)` yields
an empty list and `e.dataTransfer.files.length > 0`, set
`state.docsError` (existing field) to a short message like:

> "No supported files in drop. Accepted: .md, .txt"

Use a `runInAction(() => { state.docsError = "..."; })` since this
is a synchronous handler boundary write to an observable. No API
call should happen in this branch.

## Refresh path is automatic

`uploadDocuments` (module-level mutation) already calls the docs
refresh after a successful API call. The drop handler does not
need its own refresh.

## AbortController

`handleFileUpload` (line 261-267) does. Pass `ctrl.signal` to the
mutation. No need to retain the controller — drop is fire-and-
forget; the existing mutation handles its own try/catch.
